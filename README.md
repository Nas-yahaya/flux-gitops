# flux-gitops

GitOps repo for a local single-node kind cluster, managed by Flux.

## Layout

```
clusters/dev/            # what Flux syncs for the dev cluster
  flux-system/           # generated by `flux bootstrap` (do not edit)
  infrastructure.yaml    # -> ./infrastructure/controllers
  apps.yaml              # -> ./apps/dev (after infrastructure is ready)
infrastructure/
  controllers/           # cluster add-ons (metrics-server)
apps/
  base/podinfo/          # podinfo HelmRelease, shared by all clusters
  dev/                   # dev overlay: values patches for this cluster
kind-config.yaml         # kind cluster definition
```

## Setup

1. Create the cluster:

   ```
   kind create cluster --config kind-config.yaml
   ```

2. Create an empty private repo named `flux-gitops` on GitHub (no README or .gitignore) and push this repo to it:

   ```
   git remote add origin https://github.com/<github-user>/flux-gitops.git
   git push -u origin main
   ```

3. Bootstrap Flux against it (needs `GITHUB_TOKEN` set to a PAT with `repo` scope):

   ```
   flux bootstrap github --context=kind-dev --owner=<github-user> --repository=flux-gitops --branch=main --path=clusters/dev --personal --private=true
   ```

   Bootstrap commits `clusters/dev/flux-system/` to the repo, so run `git pull` afterwards.

4. Watch it reconcile:

   ```
   flux get kustomizations --watch
   flux get helmreleases -A
   ```

5. Open podinfo:

   ```
   kubectl -n podinfo port-forward svc/podinfo 9898:9898
   ```

   Then browse to http://localhost:9898.

## Making changes

Edit manifests, commit and push. Flux applies them on the next sync, or immediately with:

```
flux reconcile kustomization flux-system --with-source
```
